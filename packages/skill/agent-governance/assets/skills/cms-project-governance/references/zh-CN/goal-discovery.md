# 目标发现 2.1

当用户知道概念、痛点、方向或期望结果，但不知道中间执行路径时使用。

## 低负担访谈

每轮最多问三个问题，并且只有答案会实质改变目标、受益者、最小有用流程、可观察成功、安全/隐私/数据/成本边界，或昂贵不可逆选择时才问。除非技术选项会改变用户可见取舍，否则不要要求非技术用户选择框架或架构。

用户不知道时，给出两三个白话选项，说明实际差异，推荐一个可逆默认值，并标记为 AI 假设。不要重复询问对话或项目中已有的事实。

## 意图模型

分开记录期望结果、受益者与场景、当前问题、最简单有用结果、已知限制、确认事实、AI 推断和待确认事项。不能把推断写成事实。

对所需证据分类：

- Runtime 行为；
- Contract/接口一致性；
- Governance/流程控制；
- Artifact 存在与质量；
- Mixed，并标注每条标准。

若目标是 Runtime，必须说明真实用户或操作人员如何演示成功。除非目标本身就是产物，否则 Schema、类型检查、构建、文档或截图不能单独证明功能可用。

## 准备度阶梯

| 状态 | 需要理解 | 下一步 |
| --- | --- | --- |
| `Concept` | 大致想法或痛点 | 澄清结果与受益者 |
| `Direction` | 结果与主要用途 | 提议最简单有用流程 |
| `Ready for Planning` | MVP 边界与成功证据 | 分类并分级目标 |
| `Ready for Execution` | 范围、验收、限制与权限 | 派发一个 Packet |
| `Owner Decision Required` | 无法推断的重要选择 | 合并选项并停止 |

可逆不确定性不应阻塞。记录假设，并采用最安全、低成本的默认值。

## 输出

使用 `{baseDir}/templates/zh-CN/INTENT_BRIEF.md`。除非进入规划、用户要求保存或另一个 Agent 需要持久交接，否则只在对话中保留。结尾只给一个建议动作、为何优先及它应产生的证据。
