# 隔离型委派 2.1.1

## 目的

用 Worker 把高输出调查和工具结果隔离在协调上下文之外。委派是上下文边界，不是默认角色仪式，也不是完成证据。

## 何时委派

任务可分离且符合一项以上条件时委派：

- 预计检查超过 6 个文件；
- 预计有效工具输出超过约 10,000 字符；
- 需要扫描日志、历史、大范围只读状态或嘈杂测试套件；
- 独立 Reviewer 需要任务局部证据；
- 并行 Work Order 有不重叠写入范围和已授权集成阶段。

小型、高耦合、需要反复澄清，或 Worker 必须重读大部分协调上下文的工作留在主 Loop。

## Worker 任务包

只发送：

- 一个有界问题或结果；
- 相关项目相对路径；
- 该结果所需验收项；
- authority fingerprint 和必要摘录，不发送全部治理文件；
- 读写范围及禁止边界；
- 命令和输出预算；
- 结构化回传要求。

禁止发送完整父对话、无关历史、期望判定、密钥或可复用 Session。

## 并发与写入

- 默认最多 3 个活跃 Worker。
- Active Packet 与 Loop Runs 只有一个协调写者。
- 并行 Developer 使用不重叠 Work Order 和文件范围。
- 范围重叠时串行执行，或指定唯一实现写者。
- Worker 不修改治理权威；除非被独立授权为该角色，否则不能签最终验收。

## 回传契约

不回传隐藏推理或完整命令输出：

```yaml
result: Pass | Fail | Inconclusive
progress_delta: "可观察变化或发现"
files_read: 0
files_changed: []
evidence: []
failure_signature: null
risks: []
recommended_next_action: "唯一动作"
return_chars: 0
```

允许时，把大型原始输出放进项目内一次性证据。只回传命令、退出码、精简摘要、有效失败尾部和证据路径。

## 成本检查

只有减少协调上下文保留量或产生必要独立性时，委派才成功。平台提供真实用量时记录；否则比较读取文件数、回传字符、工具输出字符和重复读取。若 Worker 重读大部分父材料或回传长篇过程，下次改为直接执行。
