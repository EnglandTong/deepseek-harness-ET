# Agent Note：Personal Supervisor 项目注册表

Status: implemented

[English](2026-08-31-supervisor-project-registry.md) | 中文

## 问题

Personal Supervisor 需要在不静默纳管目录的前提下建立项目身份，也不能把路径别名当成不同项目。发现必须有界且只读元数据，显式纳管必须使用唯一规范路径，移除不能删除项目数据。

## 决定

`@deepseek-ai/dsh-supervisor-project-registry` 接受明确的发现 roots，只枚举第一层目录项，对存在的目录通过 `realpath` 规范化，并在用户明确注册后发出版本化 `supervisor/project` 快照。注册变更串行执行，因此并发别名不会发布重复所有者。刷新不会跟随已改变的规范目标，并将缺失或非目录路径报告为不可用；权限错误仍作为失败返回。它记录这些观察而不写项目文件，并使用 `.git` 文件标记识别 linked worktree。从中央总控总账恢复的注册即使总账重放晚于注册表构造也保持可见：注册表在每个公共入口点以累加方式合并尚未观察到的中央项目，且从不重新发布它们，因此被恢复的真实路径保留其原所有者。

## 备选方案

- 拒绝扫描整个文件系统，因为它无界且会产生未经确认的项目候选。
- 拒绝使用显示路径作为身份，因为符号链接和 junction 别名会产生重复项目。
- 拒绝在发现阶段读取项目清单，因为候选发现必须保持元数据只读。
- 拒绝在取消纳管时删除项目目录，因为中央纳管关系与用户项目数据相互独立。

## 后果

一个规范路径在别名、并发注册和重启之间保持唯一所有者，移除只改变中央纳管关系——supervisor 永不删除用户拥有的项目数据。代价是 Windows 对每一种链接类型都不提供可移植的末端组件区分，因此 Provider 将 Windows 上的每个链接都报告为 junction，并把规范身份作为安全不变量。

## 测试

`packages/supervisor/supervisor-project-registry/tests/registry.spec.ts` 钉住只发现第一层目录项且不自动纳管、realpath 别名去重并覆盖并发规范化、对中央总账在构造后恢复的真实路径去重、注册/刷新/移除共用一个变更队列、worktree 与链接元数据报告、拒绝注册缺失或非目录路径、幂等移除，以及刷新从不跟随已改变的符号链接目标。
